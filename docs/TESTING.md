# LITVERSE 검증 기록

검증일: 2026-11-01. Windows, Node.js 24.18.0, npm 11, Microsoft Edge 기반 Playwright에서 실행했습니다.

## 공통 헤더·수업 카드·빈 전시관 검증

- `tests/e2e/screens.spec.js`에서 기존 18가지 크기와 사용자 화면에 가까운 1215×842를 포함한 19가지 크기를 검사했습니다. 상단 메뉴를 클릭해 세 화면을 이동해도 헤더·로고·각 메뉴의 좌표와 크기가 동일합니다.
- 수업 만들기, 작은 책 표지 형태의 수업 카드, 빈 전시관의 일러스트·안내·첫 수업 시작하기, 푸터까지 한 화면에 표시되며 가로·세로 넘침이 없습니다.
- 긴 제목과 학급명을 가진 수업 20개를 만들어 이전·다음으로 모두 접근했습니다. 1366×768 → 320×520 → 844×390 크기 변경 시 페이지 크기와 현재 위치를 조정하고, 키보드 이동과 마지막 수업의 비밀번호 화면 진입을 확인했습니다.
- 완성 포스터 13개가 있는 전시관은 본문이 자연스럽게 스크롤됩니다. 마지막 작품까지 이동해도 헤더 위치는 유지되고, 상단 수업하기로 이동하면 화면 맨 위로 돌아옵니다.
- PC·모바일·가로 화면 캡처는 `test-results/screens/`에 생성됩니다. 서버·DB 변경은 없으며 아래 24개 서버 검사는 기존 검증 결과입니다.

## 메뉴·버튼 단순화 검증

- 공통 상단 메뉴로 메인·수업하기·관람하기를 이동하고 현재 위치를 표시합니다. 수업 목록의 대시보드·하단 모바일 메뉴·이어가기 배너·완료 목록을 제거했습니다.
- 빈 수업 목록에서도 생성 버튼은 한 개이며, 수업 카드 자체가 하나의 링크로 동작합니다. 완료작은 관람 화면에서만 보이고 상세 화면에서 비밀번호를 확인한 뒤 다시 열 수 있습니다.
- 분석 탭과 중복되는 제목·단계 안내를 줄이고 수업 설정에 진행 관리·제출 현황을 모았습니다. 최종본은 마무리 화면에서 선택합니다.
- 갤러리의 필터·정렬·보기 기능은 접을 수 있으며 적용된 필터 수를 표시합니다. 키보드로 펼치기, 크게 보기 전환, 조건 검색을 검사했습니다.
- 수업 생성·수정·삭제·비밀번호 확인·전시 완료와 정적 경로·단일 HTML 흐름을 함께 회귀 검사합니다. 최신 실행 결과는 아래 표에 기록합니다.

## 반응형 입구 고도화 검증

전시관 입구 레이아웃과 안내 일러스트를 개선했으며, 이후 공통 메뉴와 수업 UI 정리에서도 아래 화면 크기 검사를 다시 실행했습니다.

- 320×520, 320×568, 360×640, 375×667, 390×844, 412×915, 600×800, 768×1024, 820×1180, 1024×768, 1280×720, 1366×768, 1440×900, 1920×1080, 2560×1440, 568×320, 667×375, 844×390의 18가지 크기에서 메인 화면의 세로·가로 스크롤 없이 제목·두 입구·전시 현황·푸터가 표시되는지 검사했습니다.
- 카드 제목·상단 안내·하단 링크가 카드 경계 안에 들어오는지, 일러스트가 실제 로딩되는지 확인했습니다.
- 390px 너비에서 높이를 620→750→600→844px로 바꾸어 모바일 주소창에 따른 재배치를 확인했습니다.
- 완료작이 없으면 전시 현황은 0점이며, 진행 중인 수업이 있어도 집계하지 않습니다. 완료 포스터 13개가 있으면 13점으로 표시하고, 전체 보기에서 키보드로 전시작 13개에 접근하는지 확인했습니다.
- 극단적으로 작은 320×300 화면에서는 정상 스크롤로 선택지에 접근할 수 있습니다. 일반 화면의 수업 목록은 페이지로 넘기며, 작품이 있는 전시관 목록은 자연스럽게 스크롤합니다.
- `test-results/entrance/`의 1366×768 PC, 390×844 모바일, 320×568 소형 화면, 844×390 가로 화면 캡처를 직접 확인했습니다.
- 관람하기와 빈 전시관에 새 수채화 전시실 일러스트를 사용하며, 파일·프롬프트는 [삽화 기록](ART-PROMPTS.md)에 있습니다.

## 문학 전시관·완성 포스터

- 수업 암호의 잘못된 입력 거절, 직접 API 호출 거절, 올바른 암호로 이어가기와 관리자 전체 수업 접근을 확인했습니다.
- 수업 마무리에서 인물·사건 한 장씩 선택 → 줄거리·배경·성격·사건·서명 입력 → 미리보기 → 18장 삭제 확인 → 전시 완료를 실제 브라우저에서 실행했습니다.
- 예시 수업의 20장 중 정확히 두 장만 남고, 18명 분석 글은 유지됩니다. 비밀번호 없이 공개 포스터는 볼 수 있지만 수업 수정은 차단됩니다.
- 액자 목록·제작자 서명·완료 수업 구분, 완료 후 암호 확인과 다시 열기, 재개 시 전시 내림, 관리자 암호 재설정·수업 삭제를 확인했습니다.
- 포스터 HTML에 실제 이미지 data URL이 포함됩니다. 일반 포스터와 긴 글을 담은 독립 HTML을 PDF로 출력하여 각각 한 페이지인지 확인했습니다.
- DB 테스트에서 최종본 선택 유형 검증, 다른 수업 소유자의 요청 차단, 암호 테이블 접근 차단, 완료 후 수정·사진 삭제 차단, 삭제 작업 실패 후 재시도와 선택 사진 보존을 확인했습니다.
- OpenAI API는 모의 응답으로 구조화 출력·작품 식별 실패·거절·키 누락 처리를 검사했습니다. 실제 키가 없어 유료 API 호출은 실행하지 않았습니다.

## 확인한 수업 흐름

- 첫 접속에서 좌우 수업하기·관람하기 입구를 표시하며, 수업 선택 전이나 새 수업 작성 중에는 프로젝트 활동 탭을 표시하지 않습니다.
- 빈 수업 목록에서 수업 만들기 → 작품·학급·설정 입력 → 저장 → 배경 탐구로 이동 → 세 탭 표시를 확인했습니다.
- 두 수업을 생성해 질문과 제출물의 수업별 분리, 수업 정보 수정 후 새로고침 복원, 수업 카드로 다시 열기, 새 수업 작성 취소를 확인했습니다.
- 등장인물 갤러리는 인물 사진만, 사건 분석은 사건 기록과 장면 사진만 표시합니다. 사진이 없는 학생의 사건 분석도 읽을 수 있으며 사건 이름·학생 번호 검색과 탭 새로고침을 확인했습니다.
- 교사가 시간적 배경 질문 공개 → 모바일 학생 응답 → 교사 화면 취합 → 최종 정리 공유. 공간적 배경도 같은 흐름으로 확인했습니다.
- 교사가 분석 단계로 전환하면 학생 화면도 인물·사건 분석으로 전환되고 배경 정리가 표시됩니다.
- 학생은 인물의 성격과 본문 근거·해석 이유를 작성하고, 다음 탭에서 인상 깊은 사건과 이유를 작성합니다. 두 프롬프트에 시간적·공간적 배경 정리가 포함됩니다.
- 모바일에서 임시저장·새로고침 복원, 두 프롬프트 완성, 인물과 사건의 독립적인 업로드를 확인했습니다. 한 종류만 제출하면 미완료이고, 두 종류를 모두 제출해야 완료됩니다.
- 교사의 인물·사건 취합, 검색·필터·승인·비교·삭제·태그 매핑, QR 창과 단계 변경을 확인했습니다.
- 데이터 내보내기에 배경 질문·학생 응답·교사 정리가 들어가고 개인 제출 코드와 QR 토큰은 제외됩니다. 내려받은 JSON을 실제로 파싱했습니다.
- 320, 390, 768, 1024, 1366, 1920px 너비 및 844×390 가로 화면에서 주요 페이지의 가로 넘침과 선택 메뉴 경계를 검사했습니다.
- 320px 모달의 포커스 순환, Escape 닫기, 배경 inert, 원래 버튼으로 초점 복귀를 확인했습니다.
- 승인 작품만 전시되는지, reduced-motion에서 즉시 표시되는지, 태그 필터와 작품 이동이 동작하는지 확인했습니다.
- 데모 저장소에 30명의 분석과 각 2장씩 60장을 만들어, 1920×1080 전시에 이미지가 모두 로딩되고 원본 비율로 화면 안에 표시되는지 확인했습니다.

## GitHub Pages·단일 HTML 검사

`tests/pages/static.spec.js`는 Vite 개발 서버 대신 SPA fallback이 없는 정적 서버와 실제 `file://` 파일에서 검사합니다. 웹폰트 요청은 차단하여 외부 폰트 없이도 동작하는지 확인했습니다.

- 사이트 루트, `/preview-repository/` 하위 경로, `release/index.html` 직접 열기에서 동일한 수업 생성·질문 저장 흐름을 실행했습니다.
- 저장 후 새로고침, 뒤로·앞으로 이동, 활동 링크 새 탭 열기, 본문 바로가기 동작을 확인했습니다.
- 예시 인물 사진 12장이 모두 로딩되는지 검사했고, 단일 HTML에서는 이미지가 내장 data URL인지 확인했습니다.
- 학생 QR 링크가 해당 배포 경로의 `#/submit/...`를 가리키고, 학생 화면 이동·새로고침 후에도 정상 표시되는지 확인했습니다.
- 인물·사건 최종본 선택, 완성 포스터와 서명, HTML 다운로드, 한 페이지 PDF 출력, 액자 전시를 세 배포 경로에서 확인했습니다.
- 실제 GitHub Actions 실행 및 원격 배포는 GitHub 계정 인증과 저장소 연결 후 확인해야 합니다.

## 데이터베이스·서버 검사

PGlite PostgreSQL에 세 SQL 마이그레이션을 실제 적용했습니다. 테스트용 Auth·Storage 스키마와 역할을 사용합니다.

- 교사 소유권 RLS, 학생 응답 비공개, 서비스 역할 전용 RPC.
- 질문 마감 뒤 응답 차단, 동일 학생의 응답 수정, 교사 정리의 원자적 반영.
- 활동지 재시도 중복 방지, 재발급 이전 코드 차단, 사건 분석 필수 검증.
- 업로드 슬롯 중복 예약 차단, 완료 재호출의 멱등성, 제출 단계 재검사, 교체 파일 정리 예약.
- 이미지 삭제 시 분석 보존, 활동 삭제 시 연관 자료 정리, 삭제 중 새 제출 차단.
- 지속성 요청 제한, 30건의 분석 요청과 60건의 이미지 등록.
- 서버 입력 검증, 출처가 다른 요청·잘못된 JSON 차단, 허용 파일 시그니처 검사.

이 검사는 실제 Supabase 서버에 30대의 휴대폰을 연결한 부하 시험은 아닙니다.

## 남은 운영 검증과 제약

- 코드는 비공개 GitHub 저장소에 보관합니다. Supabase 연결과 Netlify 배포는 사용자 요청으로 보류했으며, 실제 Auth, Storage, Realtime 연결은 검증하지 않았습니다. 설정 순서는 [README](../README.md)에 있습니다.
- 모바일 검사는 Edge의 화면 크기 에뮬레이션입니다. 실제 iOS Safari·Android의 가상 키보드, 카메라 QR 진입, 학교 네트워크는 운영 연결 후 확인해야 합니다.
- 데모 데이터는 같은 브라우저의 탭끼리만 동기화됩니다. 여러 기기로 수업하려면 실서비스 모드를 설정해야 합니다.
- 밝은 전시관 개편에서 회전하는 Three.js 장식을 제거했습니다. 현재 빌드에는 해당 705KB 청크가 포함되지 않고, 청크 크기 경고도 없습니다.
- 학생 배경 화면은 운영 모드에서 15초 간격으로 갱신됩니다. 교사 화면은 Realtime과 재조회 보완을 사용합니다.
- 파일 선택기 자체는 운영체제 기능입니다. 앱의 콤보박스·확인창·상세창·오류 안내는 커스텀 UI입니다.
