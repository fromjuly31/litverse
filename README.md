# LITVERSE

**한 편의 소설, 서로 다른 시선.** 고등학교 문학 수업에서 배경·인물·사건을 함께 읽고, 학생의 해석을 두 장의 작품으로 전시하는 웹 플랫폼입니다.

학생은 모바일, 교사는 노트북·데스크톱을 중심으로 사용합니다. 밝은 종이색 배경과 작품을 크게 건 전시 벽, 명조 제목으로 문학 전시관을 표현합니다. Vanilla JavaScript ES Modules, Vite, GSAP, Lucide, Supabase, Netlify Functions로 구성했습니다. 앱 안에서는 이미지 생성 API를 호출하지 않습니다.

## 수업 흐름

기본 화면은 **메인 / 수업하기 / 관람하기** 세 가지입니다. 메인 화면은 문학 전시관 입구이며, 좌우의 **수업하기 / 관람하기**에 마우스를 올리면 작품 배경이 밝아집니다. 모든 화면의 우측 상단 메뉴로 수업과 관람을 전환하고, LITVERSE 로고로 메인에 돌아옵니다. 수업하기에는 **수업 만들기**와 **진행 중인 수업**만 표시합니다. **수업 만들기 → 작품·학급·수업 설정 입력 → 수업 저장** 순서로 수업 프로젝트를 만듭니다. 수업을 열면 **배경 탐구 / 등장인물 갤러리 / 사건 분석** 세 탭이 나타나며, 질문·응답·분석·사진은 해당 수업에 연결됩니다. 수업 진행 단계와 정보 수정은 프로젝트 상단의 **수업 설정**에서 관리합니다.

진행 중인 수업 카드를 클릭해 이어서 참여합니다. 별도 대시보드 메뉴나 모바일 하단 메뉴는 없으며, 새 수업 작성 중에는 이전 수업의 활동 탭을 표시하지 않습니다. 완료된 수업은 **관람하기**에서 확인하고, 작품 상세 화면의 **수업 다시 열기**로 비밀번호 확인 후 수정할 수 있습니다. 사건 분석 탭은 장면 사진을 제출하기 전에도 학생이 완성한 사건·선택 이유·본문 근거를 보여 줍니다.

수업 안에서는 **수업 설정 / 수업 마무리**와 세 분석 탭을 사용합니다. 진행 단계·정보 수정·제출 현황은 수업 설정에 모았습니다. 갤러리의 조건 검색·정렬·인물 해석 비교·크게 보기·전체 화면 전시는 **필터 · 보기 옵션**을 펼치면 이용할 수 있으며, 최종 사진 선택은 수업 마무리에서만 합니다.

1. **작품 등록**: 제목·원작 작가·학급·소개·수업 목표·이미지 스타일과 수업 비밀번호(8~128자)를 입력합니다. 제목과 작가를 입력하면 AI 줄거리 초안을 가져오며 직접 수정할 수 있습니다.
2. **배경 탐구**: 교사가 시간적 배경과 공간적 배경 질문을 공개합니다. 학생은 활동 QR로 접속해 본문을 근거로 응답합니다. 교사가 실시간으로 응답을 모아 최종 정리를 공유합니다.
3. **인물 해석**: 학생이 인물의 성격을 쓰고, 바로 아래에 왜 그렇게 생각했는지 본문 근거와 연결 이유를 작성합니다. 성격을 표현할 외모·표정·눈빛도 구체화합니다.
4. **사건 해석**: 다음 탭에서 인상 깊은 사건과 선택 이유, 본문 속 전개, 인물의 행동, 시각화할 장면을 작성합니다.
5. **두 프롬프트**: 교사의 시간적·공간적 배경 정리와 학생의 해석을 결합해 인물 초상화 및 사건 장면 프롬프트를 각각 만듭니다. 외부 AI에서 사진을 생성합니다.
6. **두 사진 제출**: 제출 QR과 개인 코드로 접속합니다. 첫 탭에 인물 사진 한 장, 두 번째 탭에 사건 장면 사진 한 장을 제출합니다. 한 장만 제출하면 전체 완료로 표시하지 않습니다.
7. **취합·토론·전시**: 교사는 인물·사건 탭에서 각각의 작품을 확인하고 승인합니다. 학생별 두 사진 제출 상태, 성격 태그, 본문 근거, 사건 선택 이유를 살펴보며 비교·전시합니다.

8. **최종본·포스터 완성**: **수업 마무리**에서 인물 1장·사건 1장을 선택합니다. 줄거리·배경·성격·사건을 다듬고 **전시작 제작자 이름**을 입력합니다. 원작 작가와 제작자 서명은 구분됩니다. 미리보기 후 최종 완료하면 나머지 사진을 삭제하고, 정확히 두 장과 분석 글을 보관합니다.
9. **관람하기**: 완성 포스터를 액자 형태로 전시합니다. 작품·원작 작가·제작자 검색과 24점 단위 추가 조회를 지원합니다. 클릭하면 전체 포스터를 보고, 이미지까지 내장한 HTML로 저장하거나 한 장의 A3 PDF로 인쇄할 수 있습니다. 긴 글은 인쇄 때 한 장에 맞춰 축소됩니다.

단계는 `DRAFT → BACKGROUND → ANALYSIS → SUBMISSION → CLOSED`입니다. 단순 제출 마감과 최종 전시 완료는 구분됩니다. 전시 완료는 사진과 포스터를 확정한 수업입니다.

수업을 떠났다가 목록에서 다시 열면 처음 설정한 비밀번호가 필요합니다. 완료된 수업은 잠기며, 암호 확인 후 명시적으로 **수업 다시 열기**를 눌러 수정합니다. 수정 중에는 전시에서 내려가고 다시 완료하면 재전시됩니다. 삭제한 사진은 복구되지 않습니다. **관리자 로그인**에서는 모든 수업 열기·수정·삭제와 암호 재설정이 가능합니다.

## 로컬 실행

완성된 HTML 파일은 **`release/index.html`**, GitHub Pages 배포 폴더는 **`github-pages/`**입니다. 생성 파일은 Git에 포함하지 않으며 `npm run build:pages`로 다시 만들 수 있습니다. 단일 HTML 직접 열기와 수동 배포 방법은 [GitHub Pages 안내](docs/GITHUB-PAGES.md)에 정리했습니다.

Node.js 24와 npm을 사용합니다.

```sh
npm ci
npm run dev
```

브라우저에서 `http://localhost:5173`을 엽니다. 기본값은 **데모 모드**입니다.

- 문학 전시관 입구: `/`
- 완성작 관람: `/exhibition`
- 관리자: `/admin`
- 수업 화면: `/teacher`
- 수업 만들기: `/teacher/activities/new`
- 배경 수업: `/teacher/activity/demo-dongbaek/background`에서 **배경 탐구 시작**
- 등장인물 갤러리: `/teacher/activity/demo-dongbaek/gallery`
- 사건 분석: `/teacher/activity/demo-dongbaek/scenes`
- 수업 설정: `/teacher/activity/demo-dongbaek/settings`
- 학생 활동: `/activity/demo-dongbaek-analysis`
- 사진 제출: `/submit/demo-dongbaek-submit`
- 샘플 학생 제출 코드: `demo-student-1` ~ `demo-student-18`

데모는 IndexedDB와 BroadcastChannel을 사용합니다. 같은 브라우저의 여러 탭은 동기화되지만 **서로 다른 기기는 데이터를 공유하지 않습니다**. 초기 자료는 학생 18명, 인물 사진 12장, 사건 사진 8장으로 일부 제출 상태를 보여 주는 예시입니다. 데모 일러스트레이션과 분석은 실제 학생 자료가 아닙니다. 관리자 설정에서 데모를 초기화할 수 있습니다. 기존 예시 수업은 처음 열 때 비밀번호를 직접 정합니다. 데모 관리자도 `/admin` 첫 방문에서 직접 설정하며 기본 공용 암호는 없습니다. 데모 암호는 PBKDF2로 저장하지만 브라우저 저장소를 직접 변경할 수 있으므로 실제 접근 통제 수단이 아닙니다.

## 파일 구조

```text
src/
  components/     커스텀 콤보박스·모달·토스트, 작품 카드, 학생 탭
  pages/          수업 목록, 배경 문답, 분석·제출, 갤러리·전시
  services/       Supabase/Netlify 연결 및 별도 데모 저장소
  styles/         디자인 시스템, 반응형, 배경·인물·사건 화면
  utils/          프롬프트, 실제 태그 통계, 파일 검증·압축
netlify/
  functions/      API 및 매시간 업로드·삭제 정리 함수
  lib/            서버 인증·검증·토큰·삭제 처리
supabase/migrations/
  001_litverse.sql
  002_background_discussion.sql
  003_exhibition_archive.sql
public/art/       전시용 AI 예시 삽화와 기존 데모 자산
tests/            도메인·보안·SQL·Playwright 테스트
docs/             아키텍처와 검증 기록
```

## Supabase 설정

1. Supabase 프로젝트를 생성합니다.
2. SQL Editor에서 `supabase/migrations/001_litverse.sql`, `002_background_discussion.sql`, `003_exhibition_archive.sql`을 **순서대로 한 번씩** 실행합니다.
3. 테이블, 인덱스, 소유권 RLS, 서비스 전용 함수가 생성됩니다. Realtime publication이 있는 Supabase 프로젝트에서는 관련 테이블도 등록됩니다.
4. `literature-images` Storage 버킷이 SQL에 의해 **Private**으로 생성됩니다. 허용 형식은 JPEG·PNG·WebP, 저장 파일 한도는 5MB입니다. 이미 같은 이름의 버킷이 있으면 기존 공개 정책이 없는지 확인합니다. 학생용 공개 읽기/쓰기 정책을 추가하지 않습니다.
5. Authentication 설정에서 **공개 신규 가입을 비활성화**합니다. 앱에는 가입 화면이 없습니다.
6. 관리자 화면에서 교사 계정을 생성하고 이메일 확인을 완료합니다.
7. 생성한 Auth 사용자 UUID로 교사 프로필을 등록합니다.

```sql
insert into public.teacher_profiles (id, email, is_admin)
values ('생성한-관리자-사용자-UUID', 'admin@example.school', true);
```

운영 관리자 로그인에는 `teacher_profiles.is_admin=true`가 필요합니다. 기존 관리자 프로필은 SQL Editor에서 `update public.teacher_profiles set is_admin=true where id='관리자-UUID';`로 지정합니다. 기존 수업의 비밀번호는 관리자 화면의 **암호 재설정**에서 설정합니다. 새 공개 수업은 최초 등록 관리자 소유로 생성하며, 해당 수업 암호를 검증한 세션만 관리 API를 호출할 수 있습니다. 관리자는 전체 수업에 접근합니다. DB의 직접 쓰기는 서비스 역할에만 허용됩니다. 학생은 Supabase 계정 없이 QR 토큰 및 개인 코드를 사용하며, 다른 학생의 응답이나 분석을 조회할 수 없습니다.

## 환경변수

`.env.example`을 참고합니다. 실제 키는 저장소에 커밋하지 않습니다.

| 변수                        | 범위                     | 값                                     |
| --------------------------- | ------------------------ | -------------------------------------- |
| `VITE_APP_MODE`             | 브라우저 빌드            | 데모 `demo`, 실서비스 `live`           |
| `VITE_SUPABASE_URL`         | 브라우저 빌드            | Supabase 프로젝트 URL                  |
| `VITE_SUPABASE_ANON_KEY`    | 브라우저 빌드            | 공개 anon/publishable 키               |
| `VITE_PUBLIC_SITE_URL`      | 브라우저 빌드            | 실제 HTTPS Netlify 주소, 끝의 `/` 제외 |
| `SUPABASE_URL`              | 서버 Functions 전용      | 같은 Supabase URL                      |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 Functions 전용·비밀 | 서비스 역할 키                         |
| `TOKEN_SECRET`              | 서버 Functions 전용·비밀 | 최소 32바이트의 무작위 비밀            |
| `SITE_URL`                  | 서버 Functions 전용      | 실제 HTTPS 배포 주소                   |
| `OPENAI_API_KEY`            | 서버 Functions 전용·비밀 | AI 줄거리 요약용 OpenAI API 키           |
| `OPENAI_SUMMARY_MODEL`       | 서버 Functions 전용      | 기본 `gpt-4.1-mini`, 필요하면 변경       |

`TOKEN_SECRET`은 암호학적 난수로 직접 생성합니다. 노출하거나 `VITE_` 접두사를 붙이지 않습니다. 운영 도중 변경하면 기존 QR과 제출 코드가 무효화되므로 유지해야 합니다.

실서비스를 로컬에서 확인할 때는 `.env`를 설정하고 다음을 실행합니다. 최초 실행 시 Netlify CLI가 설치될 수 있습니다.

```sh
npm run dev:netlify
```

`npm run dev`는 프론트엔드 전용입니다. 실서비스 API는 Netlify Dev 또는 실제 Netlify 배포에서 실행합니다. `live` 설정이 불완전하면 오류를 표시하며 데모로 몰래 전환하지 않습니다.

## GitHub 연결과 Netlify 배포

코드는 비공개 저장소 [fromjuly31/litverse](https://github.com/fromjuly31/litverse)에 보관합니다. 현재는 코드 보관만 진행하며, Supabase 프로젝트 연결과 Netlify 배포는 보류합니다. `main`에 푸시해도 사이트가 자동 배포되지 않습니다. 아래 절차는 나중에 실서비스를 연결할 때 사용합니다.

1. 이 프로젝트를 사용자의 GitHub 저장소에 커밋·푸시합니다. `.env`, `node_modules`, `dist`, 테스트 산출물은 제외합니다.
2. Netlify에서 해당 저장소를 연결합니다.
3. 빌드 명령 `npm run build`, 게시 폴더 `dist`, Functions 폴더 `netlify/functions`를 사용합니다. `netlify.toml`에 설정되어 있습니다.
4. 위 환경변수를 등록합니다. 공개 변수는 빌드에, 비밀 변수는 Functions 런타임에 제공합니다. 실제 운영에서는 `VITE_APP_MODE=live`로 설정합니다.
5. 배포 주소를 `VITE_PUBLIC_SITE_URL`, `SITE_URL`, Supabase Auth의 Site URL에 입력하고 다시 배포합니다.
6. `/teacher`, `/activity/...`, `/submit/...` 직접 접속과 새로고침이 동작하는지 확인합니다. SPA fallback과 `/api/*` 함수 경로가 구성되어 있습니다.
7. 실제 모바일에서 HTTPS QR 링크를 테스트합니다. `localhost`는 각 기기 자신을 의미하므로 교실용 QR 주소로 사용하지 않습니다.

실서비스를 시작하려면 Supabase·Netlify 계정 연결과 환경변수 설정이 필요합니다. GitHub Pages 데모 배포도 수동 실행 시에만 동작합니다.

## 실제 수업 전 확인

- 수업 암호 검증, 다른 수업 접근 차단, 관리자 권한과 암호 재설정, 완료 후 수정 차단을 확인합니다.
- 활동 생성 → 배경 탐구 시작 → QR 응답 → 시간적·공간적 배경 최종 정리 공유를 확인합니다.
- 학생이 인물의 성격 바로 아래에 본문 근거를 쓰고, 사건 탭에서 사건과 선택 이유를 작성하는지 확인합니다.
- 두 프롬프트에 교사의 배경 정리가 포함되는지 확인합니다. 제출 코드 복사·다운로드·분실 시 교사 재발급을 확인합니다.
- 제출 단계에서 파일 선택, 붙여넣기, 압축·미리보기, **인물 한 장 + 사건 한 장** 업로드를 다른 기기에서 확인합니다.
- 교사 실시간 취합에서 두 탭과 학생별 각 제출 여부가 갱신되는지 확인합니다. 승인하지 않은 사진은 전시되지 않아야 합니다.
- 종료 후 업로드 차단, 재제출 시 해당 종류의 기존 사진만 교체, 두 장 모두 제출한 학생 수가 정확한지 확인합니다.

## AI 줄거리 요약

제목과 작가를 입력하면 OpenAI Responses API의 구조화된 출력으로 3~5문장의 줄거리 초안을 요청합니다. 작품을 확인하지 못한 경우 오류를 표시하며 내용을 만들어 채우지 않습니다. 원문 대조와 직접 수정을 지원하고, 요청 중 사용자가 편집한 내용은 덮어쓰지 않습니다. 키는 서버 환경변수에만 둡니다.

HTML·데모에서는 동백꽃, 메밀꽃 필 무렵, 소나기의 **내장 예시 요약**만 제공합니다. 실제 AI 호출로 표시하지 않으며 다른 작품은 직접 입력하거나 운영 서버 연결이 필요합니다. 실제 OpenAI API 호출과 비용은 운영 키 설정 후 발생합니다.

## 데이터 관리와 보안

- 수업 암호는 서버 scrypt로 해시하며 공개 목록에는 포함하지 않습니다. 수업 토큰은 서명된 2시간 세션이고 수업별로 제한합니다. 관리자 암호 재설정 시 버전을 올려 이전 토큰을 무효화합니다.
- 최종 전시 확정과 불필요한 사진 삭제 예약은 같은 DB 트랜잭션입니다. 전시에는 학생 번호·제출 코드 없이 선택한 두 사진과 정리한 글·제작자 서명만 공개됩니다. 완료된 수업의 수정과 이미지 삭제를 서버에서 차단합니다.
- 배경 응답과 개인 분석은 수업 암호 확인자 또는 관리자에게만 공개됩니다. 학생에게 공개되는 배경 내용은 교사가 작성한 최종 정리입니다.
- 제출 코드는 192비트 난수를 사용합니다. 서버는 HMAC 검증값만 저장하며 재발급 이전 코드는 재사용을 차단합니다.
- 업로드 경로는 서버가 정합니다. Private Storage의 signed upload token으로 직접 업로드하고, 서버가 크기·MIME·파일 시그니처를 확인한 뒤 원자적으로 등록합니다.
- 한 학생의 같은 종류에 사진이 중복 생성되지 않도록 DB 제약·업로드 작업 ID·버전 비교를 사용합니다. 인물과 사건은 서로 다른 슬롯으로 취급합니다.
- 교사는 10분 유효 signed URL로 파일을 읽습니다. 실시간 재연결과 주기적 재조회 시 URL을 새로 발급합니다.
- 이미지 삭제는 분석을 보존합니다. 학생 기록 전체 삭제와 활동 전체 삭제는 별도의 확인창을 사용합니다. 활동 삭제 시 배경 문답도 함께 정리됩니다.
- 파일과 DB의 삭제가 부분 실패하면 `deletion_jobs`에 남깁니다. 설정에서 재시도하거나 매시간 정리 함수가 처리합니다. 유효한 업로드 토큰으로 파일이 다시 생길 가능성에 대비해 3시간 뒤 추가 정리도 예약합니다.
- 입력 검증, HTML 이스케이프, 지속성 있는 요청 제한, 보안 헤더를 적용했습니다. 서비스 역할 키는 프론트엔드에 포함하지 않습니다.

## 반응형과 커스텀 UI

- 메인·수업하기·관람하기는 같은 높이와 좌우 여백의 상단 헤더를 사용합니다. 화면 전환이나 스크롤바 유무로 로고·메뉴 위치가 바뀌지 않으며, 긴 전시 목록에서도 상단 메뉴가 유지됩니다.
- 수업하기는 책 표지 형태의 작은 카드로 구성합니다. 화면 크기에 맞춰 한 번에 보여 줄 카드 수를 정하고, 수업이 많으면 아래의 이전·다음 버튼으로 이동합니다. 화면을 회전해도 보고 있던 수업이 포함된 페이지를 유지합니다.
- 작품이 없는 관람 화면은 일러스트·안내·**첫 수업 시작하기**까지 한 화면에 표시합니다. 완성 작품이 생기면 검색과 액자 목록이 나타나고 자연스럽게 아래로 스크롤됩니다.
- 전시관 입구는 `100dvh`와 콘텐츠별 그리드를 사용해 일반적인 PC·태블릿·모바일에서 제목, 수업하기·관람하기, 전시 현황, 하단 안내를 한 화면에 표시합니다. 작은 세로 화면은 카드 두 개를 위아래로, 낮은 가로 화면은 좌우로 배치합니다.
- 하단의 **전시 현황**에는 완료된 포스터 수를 **전시 중인 작품 N점**으로 표시합니다. 작품이 없으면 0점이며, 진행 중인 수업은 집계하지 않습니다. **전체 보기**에서 작품 목록으로 이동합니다.
- 브라우저 주소창 높이 변화, 화면 회전, safe-area를 반영합니다. 극단적으로 작거나 확대된 화면은 접근성을 위해 정상 스크롤을 허용하며 본문을 강제로 잘라 숨기지 않습니다.
- 관람하기 카드와 빈 전시관에 전용 수채화 일러스트를 사용합니다. 생성 프롬프트와 파일 정보는 [삽화 기록](docs/ART-PROMPTS.md)에 있습니다.

- 320px 휴대폰부터 태블릿 가로·세로, 1366px 노트북, 1920×1080 전자칠판까지 레이아웃을 구분합니다.
- 모바일 입력은 16px 이상, 터치 버튼은 기본 44px 이상입니다. 안전 영역과 가상 키보드 높이를 고려하며 학생의 입력 초점을 화면 안으로 이동합니다.
- 모든 앱 선택 메뉴는 직접 만든 combobox/listbox입니다. 방향키·Home·End·문자 탐색·Enter·Esc를 지원하고 화면 밖으로 잘리지 않게 배치합니다.
- 확인·삭제·QR·작품 상세·비교 창은 공통 커스텀 모달입니다. 포커스 순환, 원래 초점 복귀, 배경 inert·스크롤 차단을 처리합니다. 브라우저 `alert`, `confirm`, `prompt`, 기본 `select`는 사용하지 않습니다.
- 파일 선택기 자체는 브라우저·운영체제에서 제공하는 파일 접근 기능을 사용하고, 앱 안의 업로드·미리보기·오류 안내는 커스텀 UI로 표시합니다.
- 입구는 두 개의 작품 배경 선택지, 관람 화면은 액자와 서명으로 구성합니다. 이미지 원본 비율을 유지하고 reduced-motion을 지원합니다.
- 예시 그림 5점은 내장 이미지 생성 도구로 제작했습니다. [파일 경로와 생성 프롬프트](docs/ART-PROMPTS.md)를 기록했으며, 실제 학생 업로드는 변경하지 않습니다.

## 테스트

도메인·DB·아카이브 테스트, 기존 브라우저 회귀 검사와 전시관 전체 흐름 검사, 정적 배포·단일 HTML 검사 3개를 제공합니다. 일반 웹 빌드와 GitHub Pages 빌드를 구분합니다. 실제 검증 결과와 남은 제약은 [검증 기록](docs/TESTING.md)에 정리했습니다.

```sh
npm test
npm run test:e2e
npm run build
npm run build:pages
npm run test:pages
```

`npm test`는 도메인·API 입력 검증과 PGlite PostgreSQL에서 실제 SQL 마이그레이션·RLS·동시 제출·삭제 처리를 검증합니다. 30명의 분석과 60개의 인물/사건 이미지를 포함합니다.

Playwright는 기본적으로 설치된 Microsoft Edge를 사용합니다. 다른 환경에서는 `playwright.config.js`의 `channel`을 제거한 뒤 `npx playwright install chromium`을 실행합니다. 테스트 스크린샷은 `test-results/screenshots`에 생성됩니다. 실제 Supabase 네트워크, Netlify 운영 환경, 물리적인 iOS/Android 키보드와 카메라는 별도 통합 검증이 필요합니다.

## 문제 해결

| 증상                                | 확인 사항                                                             |
| ----------------------------------- | --------------------------------------------------------------------- |
| 교사 로그인은 되지만 권한 오류      | `teacher_profiles`의 UUID와 Auth 사용자 UUID 일치 여부                |
| `/api/*`에 HTML이 반환됨            | 프론트엔드 Vite만 실행한 것은 아닌지, Netlify Dev/배포 여부           |
| 학생 QR이 다른 기기에서 열리지 않음 | 실제 HTTPS 주소로 재빌드했는지, 데모 모드는 아닌지                    |
| 학생 화면에 새 질문이 늦게 보임     | 학생 배경 화면은 최대 15초 간격으로 갱신                              |
| 두 장 중 한 장만 완료               | 인물·사건 탭 각각의 업로드 성공 여부 확인                             |
| 사진이 전시에 없음                  | 해당 사진의 승인 상태 확인                                            |
| 실시간 업데이트 중단                | Realtime publication, 소유권 RLS, 교사 세션·네트워크 확인             |
| 삭제 작업 실패                      | 설정 → 정리 다시 시도, Storage 권한과 Functions 로그 확인             |
| 업로드 시간 만료                    | 이미지를 다시 선택해 새 작업으로 제출. 미완료 파일은 정리 함수가 제거 |
| 웹폰트 차단                         | 시스템 글꼴로 표시되며 기능은 유지됩니다. 학교망의 jsDelivr 접근 확인 |

구현 근거: [Supabase signed upload](https://supabase.com/docs/reference/javascript/file-buckets-uploadtosignedurl), [Private Storage](https://supabase.com/docs/guides/storage/buckets/fundamentals), [Netlify Functions API](https://docs.netlify.com/build/functions/api/).
